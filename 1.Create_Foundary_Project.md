

# A. Get started with Microsoft Foundry

1. Create a Microsoft Foundry project
- Microsoft Foundry uses projects to organize models, resources, data, and other assets used to develop an AI solution. Projects are associated with an Azure Microsoft Foundry resource, which provides the cloud services required to support AI app and agent development on Azure.

- In a web browser, open Microsoft Foundry at https://ai.azure.com 
- Click on create project 

- Project name: <PROJECT_NAME>
- Foundry resource: <Globally unique AI Foundry resource>.
Subscription: <Your Azure subscription>
Resource group: <RG_NAME>
Region: <REGION>

Note: 
https://<resource-name>.services.ai.azure.com
https://<resource-name>.cognitiveservices.azure.com

## Same steps with Azure CLI (Bash / Cloud Shell)

```bash
# ---- change these values ----
RG=rg-ai901
LOC=eastus2
FOUNDRY=ai901-foundry-manav01     # must be globally unique
PROJECT=ai-project01              # unique only inside the Foundry resource
SUB=$(az account show --query id -o tsv)
```

**Step 1 — Check the Foundry resource name is available**
```bash
az rest --method post \
  --url "https://management.azure.com/subscriptions/$SUB/providers/Microsoft.CognitiveServices/checkDomainAvailability?api-version=2023-05-01" \
  --body "{\"subdomainName\":\"$FOUNDRY\",\"type\":\"Microsoft.CognitiveServices/accounts\",\"kind\":\"AIServices\"}" \
  --query "{available:isSubdomainAvailable, reason:reason}" -o table
```
- `available = True` → go to Step 2
- `available = False` → change `FOUNDRY`, or purge it if you deleted it yourself in the last 48 hours:
```bash
az cognitiveservices account list-deleted -o table
az cognitiveservices account purge --name $FOUNDRY --resource-group $RG --location $LOC
```

**Step 2 — Create the resource group**
```bash
az group create --name $RG --location $LOC
```

**Step 3 — Create the Foundry resource**
```bash
az cognitiveservices account create \
  --name $FOUNDRY --resource-group $RG --location $LOC \
  --kind AIServices --sku S0 \
  --custom-domain $FOUNDRY \
  --allow-project-management \
  --assign-identity --yes
```

**Step 4 — Create the project**
```bash
az cognitiveservices account project create \
  --name $FOUNDRY --resource-group $RG \
  --project-name $PROJECT --location $LOC
```

**Step 5 — Give yourself access to use the project in the portal**
```bash
az role assignment create --assignee $(az ad signed-in-user show --query id -o tsv) \
  --role "Azure AI User" \
  --scope $(az cognitiveservices account show -n $FOUNDRY -g $RG --query id -o tsv)
```

**Step 6 — Verify**
```bash
az cognitiveservices account show -n $FOUNDRY -g $RG --query "{name:name, endpoint:properties.endpoint, state:properties.provisioningState}" -o table
az cognitiveservices account project list --name $FOUNDRY --resource-group $RG -o table
```
Then open https://ai.azure.com → your project should be listed.

> Steps 3–4 need a recent Azure CLI. If `project create` or `--allow-project-management` is "not recognized", run `az upgrade` first.

**Cleanup**
```bash
az group delete --name $RG --yes --no-wait
az cognitiveservices account purge --name $FOUNDRY --resource-group $RG --location $LOC   # frees the name immediately
```


## After creation

![how foundary looks after creation](image1.png)

**Open your project:** portal.azure.com → Microsoft Foundry → `<your-foundry-resource>` → **Go to Foundry portal** (opens ai.azure.com)
**OR** ai.azure.com → **All resources** → your project

| Term | What it means |
|---|---|
| Foundry resource (parent) | Azure resource in your subscription. Settings, networking and billing here apply to all its child projects |
| Project (child) | Workspace for your agents, models and data. One resource can hold many projects |
| API key | Secret key for apps to call the project (prefer Entra ID / managed identity in real apps) |
| Project endpoint | URL apps use for agents, evaluations and other project features |
| Azure OpenAI endpoint | URL apps use to call deployed OpenAI models |

## Foundry portal pages (ai.azure.com)

| Page | Area | Use |
|---|---|---|
| **Discover** | Models & services | Browse the latest models and services; find starting points for an AI app |
| **Build** | Agents & workflows | Create and manage agents and multi-step workflows |
| | Models | Deploy models; fine-tune base models for your use case |
| | Tools | Add tools that agents can call to perform tasks |
| | Knowledge | Connect enterprise data to agents through Foundry IQ |
| | Guardrails | Set responsible-AI rules for content and behaviour |
| | Memory | Let models keep conversation context across sessions |
| | Data / indexes | Connect search indexes for agents and generative AI apps |
| | Evaluations | Compare and measure model performance |
| **Operate** | Assets | Manage agents, models and tools across the project |
| | Compliance | Check and manage security and policy compliance |
| | Quota | View usage limits for models |
| | Admin | Admin tasks for your projects |
| **Manage** | Quota | Edit usage limits for models |
| | Projects | Create and manage projects under the resource |
| | AI Gateways | Set up an AI Gateway (API Management) for your models |
| | User access | Add users and give them roles (Azure RBAC, e.g. **Azure AI User**; also possible in Azure portal → resource → **Access control (IAM)**) |
| **Docs** | Documentation | Read Foundry docs, quickstarts and how-to guides inside the portal |
